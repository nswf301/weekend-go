## 이 앱의 목적 — 예약을 편하게

찾기 어려운 **예약해야 하는 곳**을 날짜로 모아 보여주는 게 목적이다. "아무 때나 가도 되는 곳"을 늘리는 앱이 아니다.
새 기능이나 자료를 붙일지 정할 땐 **"예약 칸을 채우는가"**로 판단한다.

## 지금 구조

- **수집은 전국, 자르는 건 화면이다**(2026-08-22 사용자가 정함). `collect.js` 는 17개 시·도를 전부 받고 좌표가 있는지만 본다. 화면이 **출발지에서 300km 안**(`MAX_KM`)만 보여준다. 출발지는 17개 시·도(시청·도청 자리), 기본값은 서울.
- **상시 시설은 내보내지 않는다** — `collect.js` 의 `EMIT_PLACES = false`. 수집은 그대로 하고 있어 `true` 로 바꾸면 되살아나고, 1,000곳 넘게 늘어난다. 사용자가 "다시 생각해보겠다"며 뺐다.
- **사람이 고른 장소를 넣는 자리** — `collect.js` 의 `MANUAL = []`. 지금 비어 있다. 공공데이터에 없는 곳(인스타에서 본 곳 등)을 사용자가 고르면 이름·주소·좌표를 손으로 넣는다. 수집을 다시 돌려도 남는다.
- **탭 4개** — 찾기 / 휴양림(달력·난지캠핑장 포함) / 키즈카페 / 설정.

```
index.html          화면 (data.json을 읽는다) — docs/화면.md
collect.js          자료 수집기. 거르는 규칙이 전부 여기 있다 — docs/수집규칙.md
sigun/              경기도 시군 예약 (시군 하나에 파일 하나) — sigun/지침.md
data.json           수집 결과
functions/          키즈카페 남은 자리를 세는 Firebase 함수(slots)
keys.json           인증키 (.gitignore에 있음, 절대 커밋 금지)
keys.example.json   키 넣는 자리 견본
firebase.json       함수·QR게임 Firestore 설정 (.firebaserc 의 프로젝트 weekend-go-1)
firestore.rules     QR게임이 쓰는 Firestore 규칙
nori/               즐거운 QR게임 (별개 앱)
docs/               참고 문서
```

미리보기가 필요하면 — `index.html` 의 `<script>` 앞에 `window.__DATA__` 로 data.json을 끼워 넣어 임시 파일을 만들고, 보고 나면 지운다. 자료가 박힌 사본을 남겨두면 data.json을 고쳐도 안 바뀌어 헷갈린다(예전에 1MB짜리 옛 사본이 남아 있었다).

## 배포 (다모인 앱들과 완전히 별개다)

### 화면 — GitHub Pages

이 폴더에서 아래 세 줄이면 끝이다. 1~2분 뒤 자동으로 반영된다.

```
git add -A
git commit -m "무엇을 고쳤는지"
git push
```

- 반영 확인은 `gh run list -R nswf301/weekend-go` 로 한다. `pages/builds/latest` 는 한 단계 늦은 커밋을 보여줘서 끝난 배포를 계속 기다리게 만든다.
- `C:\Users\seong\damoin-apps`(다모인 앱 모음)와는 **저장소가 다르다.** ⚠️ **이 폴더를 damoin-apps 안으로 옮기지 말 것** — 거기 `배포.bat` 이 `git add -A` 로 이 앱까지 쓸어 담는다.
- `keys.json` 은 `.gitignore` 에 있어 공개 저장소에 올라가지 않는다(확인 완료).
- `gh` 는 `C:\Users\seong\tools\bin\gh.exe`(winget이 없는 LTSC라 zip으로 설치).
- ⚠️ **2026-09-17에 커밋 기록 전체를 다시 써서 강제로 올렸다**(옛 기록 정리). 최신 파일 내용은 그대로지만 커밋 번호가 전부 바뀌었다. **다른 PC에 받아 둔 사본은 지우고 새로 받을 것**(`keys.json` 은 깃에 없으니 따로 옮긴다).

### 함수 — Firebase (키즈카페 남은 자리)

키즈카페 남은 자리를 세는 중계 함수 `slots` 하나만 Firebase에 있다(`functions/`, 서울 리전, 2026-08-20 배포). 화면을 옮긴 게 아니다.

```
cd functions && npm install          # 처음 한 번 (안 하면 배포가 멈춘다)
firebase.cmd deploy --only functions --project weekend-go-1 --account anthem82@gmail.com
```

- **PowerShell에서는 `firebase` 가 아니라 `firebase.cmd` 로 부른다.** 실행 정책이 Restricted라 npm이 까는 `firebase.ps1` 이 막힌다(`UnauthorizedAccess`). `.cmd` 를 직접 지정하면 시스템 설정을 안 건드리고 된다.
- 프로젝트 `weekend-go-1` 은 **개인 계정(anthem82@gmail.com) 소유**이고 다모인 프로젝트(nswf301 계정)와 별개다. `firebase login:add` 로 하나 더 등록해두고 `--account` 로 골라 쓴다. 로그인은 **명령을 돌리는 그 PC에서** 해야 한다. QR게임의 Firestore도 같은 프로젝트다.
- 빌드 이미지 3일 자동삭제 정책을 켜두었다 — 안 켜면 이미지가 쌓여 매달 몇백 원씩 나온다.
- 함수가 필요한 이유는 하나뿐이다 — 우리동네키움포털이 **다른 사이트에서 온 요청을 막아서**(CORS) 화면이 직접 못 묻는다. 서버끼리는 막히지 않으므로 함수가 대신 묻는다.
- 함수가 죽어도 화면은 산다. 목록과 예약 링크는 그대로 나오고 숫자만 안 보인다.

> ⚠️ **함수 안에서 날짜·요일을 다룰 땐 시간대에 기대지 말 것.** Firebase 서버는 UTC다.
> 2026-08-20에 `dayNoOf` 가 `+09:00` + `getDay()` 를 써서 토요일이 금요일로 하루 밀렸고, 요일이 안 맞으니 회차가 0개로 와 늘 "자리 없음"이 됐다. 사용자 PC(한국 시간)에서는 멀쩡해서 시험을 통과했다. 지금은 `getUTCDay()` 로 고정해 센다.
